# GitHub Repo Polish Flow

## Objetivo

Pulir el repositorio como artefacto público sin ocultar la realidad del proyecto.

## Fase Ideal

Después de que build/docs básicos sean correctos.

## Prompts Incluidos

1. `../steps/github/repo-polish.md`
2. `../steps/release/release-notes-and-checklist.md`

## Checkpoints Entre Pasos

- Inicio: `../checkpoints/build-and-compile-checkpoint.md` si el repo contiene código ejecutable.
- Final: `../checkpoints/release-readiness-checkpoint.md` si se va a publicar.

## Condiciones para Avanzar

- README no miente.
- Metadata y screenshots representan el producto.
- No hay placeholders ni claims inflados.

## Cuándo Detenerse

- El código no funciona pero la presentación intenta venderlo.
- Faltan assets reales.
- Requiere decisiones de branding o visibilidad.

## Qué Hacer si Falla Algo

Corregir metadata/docs si es seguro. Posponer publicación si el producto no sostiene la presentación.

## Resumen Final

1. Repo polish aplicado.
2. Presentación pública.
3. Riesgos.
4. Próximo paso.
