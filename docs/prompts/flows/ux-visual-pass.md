# UX + Visual Pass Flow

## Objetivo

Mejorar UX, visual quality, responsive y estados de interfaz sin tocar arquitectura innecesariamente.

## Fase Ideal

Después de que el flujo principal funcione.

## Prompts Incluidos

1. `../steps/ux/general-ux-audit.md`
2. `../steps/ux/loading-error-empty-states.md`
3. `../steps/visual/premium-visual-pass.md`
4. `../steps/visual/responsive-pass.md`
5. `../steps/accessibility/basic-accessibility-pass.md`

## Checkpoints Entre Pasos

- Después de estados: `../checkpoints/visual-ux-regression-checkpoint.md`
- Final: repetir `../checkpoints/visual-ux-regression-checkpoint.md`

## Condiciones para Avanzar

- El flujo principal se mantiene funcional.
- No hay solapes, overflow o errores visuales bloqueantes.
- Cambios visuales son acotados.

## Cuándo Detenerse

- Se requiere rediseño de producto.
- Hay conflicto entre UX y comportamiento actual.
- No se puede verificar visualmente una pantalla crítica.

## Qué Hacer si Falla Algo

Aplicar fixes pequeños. Para cambios de dirección visual o IA de producto, pedir confirmación.

## Resumen Final

1. UX mejorada.
2. Visual fixes.
3. Responsive status.
4. Accessibility warnings.
5. Pendientes.
