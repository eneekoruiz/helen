# Yearly Professional Presence Review

**Intención**: APPLY / REPORT

## Objetivo

Revisar y evolucionar anualmente toda la presencia profesional pública de una persona para responder con evidencia:

> Si alguien me descubriera hoy por primera vez, ¿mi presencia profesional representa con precisión el nivel que tengo actualmente?

No es una auditoría técnica aislada. Es una revisión transversal de posicionamiento, credibilidad, coherencia, presentación y evolución profesional.

## Cuándo usarlo

- Una vez al año y tras cambios importantes de rol, especialización o experiencia.
- Antes de buscar empleo, clientes, promoción, socios o visibilidad pública.
- Cuando portfolio, GitHub, LinkedIn y CV hayan evolucionado por separado.

## Cuándo NO usarlo

- Para auditar técnicamente un único repositorio.
- Sin permiso para modificar las cuentas o activos implicados.
- Para inventar logros, métricas, experiencia, clientes o responsabilidades.
- Como sustituto de asesoramiento legal, laboral o migratorio.

## Modo de ejecución

- **APPLY**: inspecciona, prioriza y aplica las mejoras seguras que permitan los accesos disponibles. Mantén la entrega breve.
- **REPORT**: no modifica activos; entrega una revisión priorizada y accionable.

Si no se especifica modo, usa **REPORT**. Antes de actuar, inventaría las fuentes disponibles: repositorio actual, portfolio, perfil y repositorios de GitHub, LinkedIn, CV, dominios, demos y activos públicos. Distingue siempre evidencia inspeccionada, inferencias y superficies no accesibles.

## Rol

Actúa como Staff Engineer, Product Owner, UX Lead, recruiter, hiring manager, portfolio reviewer, brand strategist, open-source maintainer y futuro yo del usuario. Evalúa tanto cada superficie como la historia profesional que forman en conjunto.

## Requisitos mínimos obligatorios

### 1. Inventario y verdad profesional

1. Inventaría las superficies públicas y documentos disponibles, incluyendo su fecha aparente de actualización.
2. Identifica la propuesta profesional actual: especialidad, seniority demostrado, problemas resueltos, audiencia y diferenciadores.
3. Separa hechos verificables de afirmaciones no demostradas. No confundas actividad, tecnologías listadas o estética con impacto.
4. Detecta información obsoleta, contradictoria, duplicada o ausente.

### 2. Portfolio

1. Revisa proyectos destacados, orden, descripciones, resultados, rol real, tecnologías y llamadas a la acción.
2. Comprueba enlaces, demos, dominios, responsive, accesibilidad, SEO, metadata, Open Graph y social previews.
3. Evalúa screenshots, GIFs, vídeo, estados reales del producto y calidad visual.
4. Revisa copywriting, jerarquía, consistencia, navegación y claridad del valor de cada proyecto.
5. Decide qué proyectos deben ganar prominencia, actualizarse, rediseñarse, fusionarse, retirarse o conservarse como archivo histórico.

### 3. GitHub y open source

1. Revisa Profile README, bio, enlaces, pinned repositories y coherencia con el posicionamiento.
2. Revisa nombres, descripciones, topics, licencias, releases, READMEs, documentación, demos, capturas y previews sociales de repositorios relevantes.
3. Identifica repositorios abandonados, duplicados, experimentales o débiles que generen ruido; recomienda mantener, mejorar, privatizar o archivar según corresponda.
4. Identifica repositorios que merecen promoción, release formal, mejores ejemplos, demo o mantenimiento renovado.
5. No juzgues calidad por volumen de contribuciones ni recomiendes actividad artificial.

### 4. LinkedIn

1. Revisa headline, About, experiencia, logros, skills, Featured, enlaces, foto, banner y URL pública cuando sean accesibles.
2. Comprueba claridad, keywords relevantes, legibilidad humana y consistencia con portfolio, GitHub y CV.
3. Convierte responsabilidades genéricas en contribuciones demostrables solo cuando exista evidencia.
4. Marca como manual cualquier cambio que no pueda realizarse con los accesos disponibles.

### 5. Resume o CV

1. Revisa audiencia objetivo, orden, relevancia, proyectos, tecnologías, logros y consistencia temporal.
2. Detecta información obsoleta, densidad excesiva, ausencias, redundancias y formato inconsistente.
3. Verifica que enlaces, nombres, fechas y afirmaciones coincidan con el resto del ecosistema.
4. Prioriza legibilidad, compatibilidad ATS y evidencia; añade elementos visuales solo cuando el formato y objetivo los justifiquen.

### 6. Marca personal y coherencia transversal

1. Compara nombre, foto, bio, tono, especialización, tecnologías, fechas, enlaces, identidad visual y proyectos destacados.
2. Identifica contradicciones, mensajes genéricos, promesas débiles, señales de seniority sin respaldo y fortalezas infracomunicadas.
3. Evalúa el primer descubrimiento: confianza inicial, prueba de capacidad, profundidad disponible y siguiente acción.
4. Comprueba que el perfil represente a la persona actual y no persiga tendencias incompatibles con sus objetivos.

### 7. Confianza y calidad pública

1. Busca enlaces muertos, certificados caducados, demos rotas, dominios abandonados, releases ausentes y contenido desactualizado.
2. Detecta screenshots pobres, previews genéricas, descripciones vagas, branding inconsistente y claims sin prueba.
3. Revisa exposición de datos personales, secretos, información sensible y riesgos reputacionales evidentes sin borrar historia legítima indiscriminadamente.
4. Exige que cada proyecto principal conduzca a código, demo, caso de estudio, resultados o explicación suficiente.

### 8. Evolución del ecosistema

1. Identifica proyectos que merecen una v2, release estable, producto, caso de estudio o mayor protagonismo.
2. Identifica proyectos que deben archivarse, retirarse de la presentación principal o conservarse solo como evidencia histórica.
3. Detecta huecos de demostración: producto end-to-end, sistemas complejos, calidad visual, arquitectura, liderazgo, open source, escritura o impacto medible.
4. Recomienda tecnologías, capacidades o proyectos de aprendizaje solo si refuerzan el posicionamiento deseado con retorno razonable.
5. Propón oportunidades de largo plazo, no una lista indiscriminada de tendencias.

### 9. Aplicación y validación

En modo **APPLY**:

1. Aplica primero mejoras locales, reversibles y respaldadas: README, documentación, metadata, copy, enlaces, orden de datos y activos.
2. Ejecuta los checks pertinentes y valida enlaces, build, responsive y previews tras modificar.
3. Usa navegador o herramientas visuales; no declares que una captura, demo o preview funciona sin inspeccionarla.
4. Respeta permisos, ramas protegidas y reglas de cada repositorio.
5. Agrupa como acciones manuales lo que requiera autenticación, criterio personal o interfaces externas.

## Más allá de estos criterios

Usa todo el repositorio, los activos públicos accesibles y el contexto disponible para descubrir oportunidades no enumeradas. Piensa primero como quien decide en pocos minutos si confiar, entrevistar, contratar, recomendar o colaborar, y después como un especialista que investiga en profundidad.

Busca desalineaciones sistémicas, no solo defectos aislados. Puede aportar más retirar ruido, enfocar la narrativa o demostrar mejor un proyecto que añadir contenido. Cuestiona la selección actual, audiencia objetivo y coste de mantener cada superficie. Prioriza crecimiento profesional sostenible, credibilidad y coherencia sobre completar una checklist.

## Límites de seguridad

- No inventes logros, cargos, clientes, métricas, testimonios, fechas, contribuciones ni experiencia.
- No publiques, archives, elimines, privatices o renombres repositorios sin autorización explícita cuando el impacto sea difícil de revertir.
- No cambies automáticamente foto, identidad personal, posicionamiento, disponibilidad laboral o contenido sensible.
- No contactes personas, publiques posts ni actives señales de búsqueda de empleo.
- No expongas datos privados, secretos, analíticas internas o información contractual.
- No rediseñes todo el ecosistema ni introduzcas dependencias sin una mejora demostrable.
- Conserva URLs, SEO y compatibilidad; propone redirecciones cuando corresponda.
- Si una superficie no es accesible, no simules haberla revisado.
- Pide confirmación antes de cambios públicos de alto impacto, irreversibles, ambiguos o reputacionales.

## Checks finales

- [ ] Las superficies disponibles y su nivel de evidencia están inventariados.
- [ ] La narrativa es coherente, actual y adecuada para la audiencia objetivo.
- [ ] Ninguna afirmación nueva carece de respaldo.
- [ ] Los proyectos principales tienen presentación, enlaces y evidencia suficientes.
- [ ] Los cambios se validaron sin romper comportamiento existente.
- [ ] Las acciones manuales son concretas y están separadas.
- [ ] Las oportunidades se priorizan por impacto, esfuerzo y alineación.
- [ ] Se registra la fecha de revisión y el siguiente período recomendado.

## Formato de entrega

### Modo APPLY

No produzcas un informe largo. Entrega solo:

#### Changes applied

Resumen breve de cambios aplicados y validaciones.

#### Manual actions required

Solo acciones que debe realizar el usuario, con superficie y acción concreta. Omite la sección si no hay ninguna.

#### High-impact opportunities

Solo oportunidades estratégicas de alto impacto. Sección opcional.

### Modo REPORT

1. Executive summary.
2. Portfolio review.
3. GitHub review.
4. LinkedIn review.
5. Resume review.
6. Personal brand consistency.
7. Ecosystem opportunities.
8. Manual actions required.
9. High-impact opportunities.
10. Recommended priorities, ordenadas por impacto, esfuerzo, riesgo y horizonte.

En ambos modos indica brevemente las superficies no accesibles y evita repetir hallazgos.
