# 05 · Final audit

Hard, honest judgment before release: code quality, i18n, documentation, public presentation and automated review. This phase finds and routes work; it does not rewrite logic.

## Quick decisions

- Run everything in order with gates: `audit-final-audit-flow`.
- Maintainability doubts: `audit-code-quality`.
- Multilingual site: `audit-i18n`.
- README or docs may promise too much: `audit-documentation`.
- The repository or project will be public: `audit-public-presentation`.
- Considering automated PR review: `audit-automated-code-review-setup`.
- Stop: produce findings and separate tasks; do not rewrite logic here.

## Exit checklist

Before moving on to 06-release:

- [ ] Code quality is PASS or PASS WITH CAVEATS.
- [ ] Documentation matches the real repository.
- [ ] Public presentation has no placeholders or false promises.
- [ ] i18n shows no raw keys or broken fallbacks.
- [ ] The design audit finds no cheap, AI or template look.
- [ ] Critical blockers are closed or explicitly accepted.
