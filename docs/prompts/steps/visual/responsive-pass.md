# Responsive Pass

## Objetivo

Verificar que las superficies principales funcionan en mobile, tablet y desktop.

## Cuándo Usarlo

- En `ux-visual-pass`.
- Antes de capturas públicas.
- Antes de release web.

## Cuándo NO Usarlo

- Si el proyecto no tiene UI responsive.

## Criterios Mínimos

- Revisa viewports pequeños, medianos y grandes.
- Busca overflow, solapes, menús rotos, botones inaccesibles, textos cortados y densidad incorrecta.
- Comprueba que el flujo principal se pueda completar.

## Más allá de estos criterios

Evalúa si cada viewport parece diseñado, no simplemente encogido.

## Límites de Seguridad

Evita reestructurar layouts grandes sin necesidad. Corrige primero los problemas visibles y bloqueantes.

## Checks Finales

- Viewports principales revisados.
- Bloqueadores responsive corregidos o documentados.

## Formato de Entrega

1. Viewports revisados.
2. Bloqueadores.
3. Fixes.
4. Warnings.
