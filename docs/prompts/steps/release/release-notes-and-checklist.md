# Release Notes and Checklist

## Objetivo

Preparar comunicación y checklist final de release.

## Cuándo Usarlo

- Al final de `release-candidate`.
- Antes de publicar, entregar o archivar.

## Cuándo NO Usarlo

- Antes de pasar build/tests/checkpoints críticos.

## Criterios Mínimos

- Revisa cambios, breaking changes, known issues, setup, screenshots, demo, changelog, versioning y release notes.
- Asegura que la comunicación coincide con lo realmente entregado.

## Más allá de estos criterios

Busca una narrativa de release clara: qué cambió, por qué importa, cómo verificarlo y qué queda fuera.

## Límites de Seguridad

No inventes mejoras. No ocultes limitaciones importantes.

## Checks Finales

- Release notes listas.
- Checklist final revisada.
- Caveats explícitos.

## Formato de Entrega

1. Release summary.
2. Checklist.
3. Known issues.
4. Sign-off recommendation.
