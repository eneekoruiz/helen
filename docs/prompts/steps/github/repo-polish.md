# GitHub Repo Polish

## Objetivo

Hacer que el repositorio sea creíble, claro y presentable sin sobreprometer.

## Cuándo Usarlo

- Antes de publicar.
- En `release-candidate`.
- En `github-repo-polish`.

## Cuándo NO Usarlo

- Si el código o docs básicos todavía fallan.

## Criterios Mínimos

- Revisa README, description, topics, About, screenshots, social preview, links, license, badges, docs y archivos de soporte.
- Detecta claims inflados, placeholders, assets débiles y señales de desorden.

## Más allá de estos criterios

Piensa como alguien que decide en 10 minutos si confiaría en el repo. Busca detalles que hacen que buen trabajo parezca mediocre.

## Límites de Seguridad

No añadas ceremonia de open source que no se mantendrá.

## Checks Finales

- README honesto.
- Metadata clara.
- Sin placeholders obvios.

## Formato de Entrega

1. Bloqueadores.
2. Fixes de presentación.
3. Riesgos de credibilidad.
4. Veredicto.
