# Repository audit — 3 October 2026

Scope: CLI commands, MCP, prompts/playbooks, skills/setup, project initialization,
filesystem mutations, rollback/ejection, generated modules/templates, evaluation
tooling, packaging, documentation, and CI commands. Compatibility was preserved
except for rejecting invalid or unsafe inputs and correcting misleading behavior.

## Findings fixed

- **File safety:** project boundary checks now distinguish sibling paths, reject
  junction/symlink escapes, and support an explicit installation root. Rollback
  cannot delete external paths or directories. Ejection checks installed state,
  file ownership, shared files and backups before modifying the project.
- **Recovery and initialization:** corrupt configuration is validated and backed
  up without overwriting earlier recovery copies. Dry runs avoid recovery writes.
  Invalid goals, agents and project names fail before initialization writes.
  Scaffold and generator names reject traversal and code/shell injection.
- **Setup:** global installation reports its files correctly, repeated setup avoids
  needless backups, and uninstall preserves unrelated agent instructions.
- **Tracking:** automatic mode runs checkpoints and pauses at instructions that
  need execution. It preserves active plans. Progress is validated, saved atomically,
  and protected against linked directories. Each checkpoint requires a fresh gate.
  Doctor reports corrupt progress while preserving it.
- **CLI and JSON:** explicit `--install` works for init/add/update and propagates
  failures. Parser/action failures return envelopes. Check and module output cannot
  contaminate JSON stdout. Animation commands return a useful JSON error; invalid
  completion shells and overlap thresholds are rejected. Empty token budgets warn.
- **MCP:** malformed messages and invalid argument types are rejected; custom
  project playbooks, zero limits, active plans and finished-state reporting are
  handled correctly. Skill listings include descriptions and installation state.
- **Prompts and budgets:** listings reflect filesystem changes, quoted hash
  characters survive frontmatter parsing, and fills treat keys/values literally.
  Budgets include flows and checkpoints and reject prototype lookups. Historical
  pricing is explicitly labelled as an estimate rather than a current quote.
- **Reports and generated entities:** report text is escaped, browser opening avoids
  shell interpolation, and report layout handles narrow widths and long strings.
  Generated pages avoid unused imports; entity defaults cannot be overwritten by
  undefined partial fields.
- **Modules:** system theme changes update the UI; Docker serves static assets from
  the correct root; production URL validation uses Vite's production flag and exact
  local hostnames. CMS/i18n/Sentry/consent output compiles with current TypeScript.
  Consent tolerates unavailable storage. PWA registration and legal placeholders
  match metadata and provide explicit integration instructions. Guardrail hooks
  handle staged paths correctly. Module execution preserves dependency versions.
- **Dependencies:** generated testing/coverage/jsdom versions were updated together
  after the sandbox exposed high/critical advisories in the old dependency tree.
- **Evaluations:** numeric options and model identifiers are validated. Prompts
  travel over stdin, available tools are restricted, and judge results require
  booleans. Failed observations cannot be paired with unrelated runs. Single-run
  differences are not labelled statistically significant, and t critical values
  no longer use the normal-distribution cutoff prematurely.
- **Distribution and docs:** npm packaging includes eval specs and their runner,
  excludes result files, declares the supported Node versions, and aligns `.nvmrc`
  with CI. English and Spanish skill inventories match the 12 bundled skills.
  The optional evaluations' provider communication is disclosed accurately.

## Verification

- `npm ci`: passed; repository dependency audit found zero vulnerabilities.
- `npm run typecheck`, `npm run lint`, `npm run build`: passed.
- Full Vitest suite: 255 tests passed across 35 files.
- `node dist/cli.js lint`: passed for prompts, indexes, playbooks, skills, catalog
  and evaluation specs.
- `npm audit --audit-level=high`: passed with zero vulnerabilities.
- npm package preview: all 12 evaluation specs and their runner present;
  no evaluation results or `.env` files included.
- CI sandbox: diagnostics, stable module dry runs and real application passed.
  Twelve scaffolded modules compiled, generated TypeScript checked, and two sandbox
  tests passed. Its upgraded dependency tree also had zero audit vulnerabilities.
- Playwright/Chromium at 375, 768 and 1440 pixels: OS theme changes, explicit theme
  persistence, CMS link editing/i18n fallback, consent denial/persistence, and a
  report containing a malicious 1,600-character project name all passed. No page,
  console or resource errors and no horizontal overflow were observed.
- PWA production build generated the service worker and Workbox assets; Chromium
  verified activation and a successful offline reload. Both standalone and
  i18n-enabled CMS scaffolds passed strict generated TypeScript builds.

## Verification limits

The local host ran Windows and Node 24. The Ubuntu/Node 22 hosted runner and
GitHub's Dependabot approval/merge actions were not executed. Paid Claude quality
evaluations were checked through validation and dry-run tests rather than provider
calls. Docker container execution was unavailable because the Docker Desktop Linux
engine pipe was missing. Real Sentry delivery and third-party hosting/account
integrations require their corresponding service setup. Legal policy files are
explicit placeholders requiring review.

Passing checks establish the tested behavior; they do not prove that every possible
defect or future dependency incompatibility is absent. Changes remain uncommitted.
