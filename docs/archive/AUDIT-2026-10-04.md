# Repository audit — second pass, 4 October 2026

This continues the [whole-repository audit](AUDIT-2026-10-03.md) and implements
additional defects found while reviewing the first pass. Scope includes CLI,
MCP, filesystem/configuration recovery, progress gates, module scaffolds,
prompt/playbook validation, reports, catalog and evaluation tooling.

## Additional findings fixed

- **Rollback failure:** a failed backup restoration could leave a tracked file
  eligible for deletion. Failed restorations now preserve the file, backup and
  configuration. A directory or unsafe path named `.helenrc` is preserved too.
- **Configuration and writes:** linked destinations and backup paths are rejected;
  non-file configuration paths are not recovered by renaming them. Failed corrupt
  configuration recovery prevents a subsequent write. Invalid JSON objects are
  rejected, and unchanged JSON/settings avoid rewrites and needless backups.
- **Progress gates:** a new check invalidates the previous success before parsing
  package scripts or executing a runner. Exceptions cannot retain a passing gate.
  Persisted gate status must agree with its recorded check results.
- **MCP transport:** tool diagnostics use stderr through a scoped logging context,
  preserving JSON stdout. MCP doctor includes agent/skill diagnostics.
- **Module results and dependencies:** scaffold overwrites are reported as modified
  files; unchanged patches are skipped. Missing dependency defaults are added
  without replacing versions already selected by the consuming project, including
  versions present in the other dependency section.
- **Catalog validation:** malformed catalog structure produces validation errors
  instead of unchecked access failures.
- **Evaluation arguments:** unknown/repeated flags and unknown skill/case or empty
  case selections fail before provider execution.
- **Reports:** report writes reject linked paths escaping the project boundary.
- **Library performance:** token-budget and playbook checks reuse prompt entries
  within each batch instead of scanning the library for every reference. New
  operations still obtain fresh entries rather than using a persistent cache.

## Third pass — retry recovery and module ownership

The next audit pass used independent read-only reviews of transport/subprocess
boundaries and module installation/ejection, followed by targeted fixes:

- **Rollback retries:** successful restorations retain their backups until all
  file mutations and configuration cleanup succeed. A later failure cannot leave
  a restored original eligible for deletion on retry.
- **Ejection retries:** restoration backups are removed only after the updated
  ownership/configuration state is committed. Backup cleanup failure is reported
  without undoing a successful ejection.
- **Failed installations:** scoped error observation distinguishes failed writes
  from ordinary existing-file skips. Failed modules report failure and produce a
  failing CLI exit status. Their partial file results remain tracked for rollback
  and retry, while they are not newly marked installed. Failed results alone do
  not trigger automatic dependency installation.
- **Actual ownership:** new installations record created and modified files per
  module. Ejection uses this record so files skipped during installation and
  unrelated backups remain untouched. Reinstallation merges prior ownership;
  updates persist new results. Legacy installations without a file history retain
  the existing metadata-based fallback rather than inventing ownership history.
- **Shared scaffolds:** declared consumers protect shared generated files even if
  they skipped their creation. The final consumer can remove the tracked generated
  file when it is ejected.
- **Ejection status:** unsuccessful ejections return a failing exit status and
  an explicit JSON result.
- **Generator identifiers:** strict-mode reserved bindings such as `arguments`,
  `eval` and `static` are rejected before generating invalid TypeScript.

Regression tests cover selective restore failure followed by retry, configuration
commit failure during ejection followed by retry, skipped-file/stale-backup
preservation, a real CLI failed installation followed by recovery and ejection,
ownership merging/validation and invalid generated bindings.

Third-pass verification passed on Node 22.23.3: clean `npm ci`, typecheck, ESLint,
all **289 tests in 35 files**, build, HELEN library lint and dependency audit
(zero vulnerabilities). `git diff --check` passed. The unchanged generated UI
passed Chromium again at 375, 768 and 1440 pixels with the interactions listed
above and no errors or horizontal overflow. External-service and hosted-runner
limits remain as stated in this report.
